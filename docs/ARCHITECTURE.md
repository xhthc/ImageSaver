# Architecture

The directory map follows the current source checkout. Existing published archives keep their original committed layout.

This document describes the v2.5.3 preview. The Explorer companion integration and file-location controls were removed. Custom save directories, author folders and the manager-return notification fix remain. The user reported working ordinary saves and smoke checks of the earlier interface; the redesigned UI has separate isolated browser checks; exhaustive audio/bytes, crash/restart and quota checks remain separate. Repository history records provenance; `SOURCE_BASELINE.json` describes the initial import, not the current release.

## Runtime layout

|---|---|
| `manifest.json` | Manifest V3 permissions, classic service worker and content scripts |
| `background.js` | Worker entry: one ordered block of worker modules, debug journal, DNR rules, context menu and selected-target hint, download tracking/badge, feedback, download lifecycle, offscreen bridge and the save entry points (context menu, inline X/Reddit/RedGIFs controls) |
| `lib/media_format.js`, `lib/download_paths.js` | MIME/signature/extension policy and media classification; file names, folder layout and authors |
| `lib/media_sources.js` | Shared HTTP(S), URL-credential and literal local/private-network admission, tied to the native selected page origin |
| `lib/candidates.js` | Candidate addresses and groups (resolution plans), thumbnail detection, scoring, the image probe and generic CDN/CMS derivatives |
| `lib/site_resolvers.js`, `lib/booru_resolvers.js` | Dedicated site adapters (X, Pixiv, Reddit, Zerochan, Anime-Pictures, Sankaku, Pawchive, ...) and booru engine families |
| `lib/page_selection.js`, `lib/x_recovery.js` | Functions injected into the clicked frame (owner admission, context target, DOM metadata) and X selected-player recovery from the owning post |
| `lib/worker/providers.js`, `lib/worker/pipeline.js` | Selected-media resolution and the original-media plan; plan execution, final MIME verification and export |
| `lib/worker/offscreen.js`, `lib/worker/animation.js`, `lib/toolbar_badge.js` | Offscreen lifetime controller, GIF/HLS conversion policy and the serialized toolbar badge |
| `content/content_context_target.js` | Capture the pressed media/CSS/overlay target; re-prove ownership at save time |
| `content/content_notifications.js` | Top-frame bounded page notices in closed Shadow DOM; original-origin delivery, dismiss/manager actions and paused timers |
| `content/content_x.js`, `content/content_reddit.js`, `content/content_redgifs.js` | Provider evidence, selected-player recovery and inline controls |
| Other `content_*.js` | Scoped site/link helpers; each script's messages define its contract |
| `offscreen.js`, `offscreen.html` | Protected buffered fetches, genuine GIF encoding and Reddit HLS assembly |
| `lib/download_manager.js`, `lib/staging.js` | Private persistent byte queue, streamed OPFS acquisition/validation, local Blob export and recovery |
| `lib/export_directory.js` | Private IndexedDB directory grants/receipts and streaming validated-file writes to a selected base directory |
| `lib/statistics.js` | Private aggregate counters and compact per-operation deduplication, without media addresses or names |
| `lib/feedback*.js`, `lib/folder_path.js` | Allow-listed records, operation tracking/notices and portable relative paths |

| `lib/gifenc.js` | Bundled GIF encoder; preserve its MIT notice |

| `ui/src/components/` | React rendering with Radix, shadcn/ui and Lucide |
| `popup/` | Committed Vite output, loaded without a developer toolchain |
| `tools/`, `tests/` | Offline checks, fixtures, build parity and commit-based packaging |

Privileged offscreen actions require the worker sender; synthetic converter test fields are refused in runtime IPC. Public-page media cannot address literal local/private destinations. The trusted selecting page origin travels only inside private queued jobs, allowing deliberately selected local-page media. Candidate/API probes and acquisition refuse unchecked server redirects before following them. The predicate does not resolve DNS or claim rebinding protection. Zerochan metadata uses the shared 2 MiB reader with its full three-second deadline and cancellation.

## Save flow

1. A gesture captures one media target and its frame/document/owner evidence.
2. Choosing **MediaLatch: Save media** revalidates that evidence. Removed, changed or ambiguous owners are refused; another post's media is never substituted.
3. Provider or generic discovery produces candidates. Preserve declared signed URLs exactly; diagnostic redaction changes only log copies.
4. Probe candidates and choose an admitted plan. A confirmed original's failure is reported rather than silently becoming a preview.
5. Prepare supported converted/assembled output if needed, then enqueue the resolved source. Up to three jobs (two per source origin) acquire complete files into offscreen OPFS storage and validate their measured bytes and media signature/container before export.
6. Persist export intent, then export the prepared file through browser downloads or write it to the user-selected directory. Browser exports attach the real Chrome ID; direct writes use a private receipt, never a fabricated Chrome ID. Direct writes report success after atomic close and size confirmation. Restart reconciles an interrupted receipt against exact staged bytes; uncertain outcomes refuse automatic retry. Known aborted pre-close failures retain prepared bytes for retry. Completed/cancelled jobs release temporary files and source addresses.

Saving controls are drafts until explicit Save. Private IndexedDB stores structured-cloned directory handles; local preferences store only a directory ID. Each queued job snapshots its destination. Grants are checked in the offscreen writer; unavailable access never falls back to Downloads. Numbered collision names preserve existing files. A cancelled pre-close write can leave an empty placeholder. Permission renewal requires choosing the same directory in settings; the handle's identity retains queued destinations. The user confirmed external-folder and X author saves in Helium on 2026-10-12. Permission lifetime across browser restart and explicit recovery remain untested.


Optional X author folders derive a strict username from the exact selected media owner's post permalink, not the page URL, reposter or quoted post's outer owner. Unknown author preserves the existing layout. The same relative path builder covers photos, videos, converted GIFs and MP4 fallback; platform-reserved usernames use the shared portable normalization. This preview also includes Reddit (author attribute of the post element that owns the selected media, by the inline control's owner rules: the author is fixed at admission: an inline save carries it in its proven descriptor, a context-menu save freezes it when the injected verifier admits the gesture (it must still be the post the gesture found), and later scrolling, removal or recycling cannot change it; comments, search cards, lightboxes, crossposts, nested posts, unproven link posts and duplicates give none) and Pixiv (`Name (user ID)` from one bounded `/ajax/illust/<id>` answer bound to the selected artwork id, shared by its batch). Other providers are not inferred.

There is no hover-based media-title network prefetch. The save item has a fixed title. Context availability remains best effort; save-time ownership checks are authoritative.

A Pawchive feed-preview save reads the owning post and saves all distinct declared supported originals, including the original cover. An individual attachment remains a single target. Post batches stop at 100 items, space starts by one second and stop on rate limits. This is a bounded adapter, not general page downloading.

## Verification and formats

Ownership precedes quality ranking. Candidate probes use headers and provider evidence; queued acquisition additionally validates the actual payload before export. The measured size and verified MIME from staging override earlier filename/header estimates. Protected Pixiv bodies, converted GIFs and supported HLS paths retain their existing transport-specific bounds.

Booru engines (BOORU-ENGINE-01): the Gelbooru family reads the selected post page's declared "Original image"/player source (whitespace-tolerant, kept exactly as written including `//images/` and the `?<post id>` query) and binds it to the clicked file hash (32-hex MD5 or the 40-hex names of safebooru.org) and, for safebooru.org-style previews, to the preview's post id. Moebooru boards (yande.re, Konachan, Sakugabooru via `www`) look up `post.json?tags=md5:` for every md5-named path (preview, sample, `/jpeg/`, image) and accept only `file_url` of that md5 on the board's own hosts; the JPEG version is not an original. Danbooru accepts `file_url`/the original variant of the same md5 on `donmai.us`; `large_file_url` (a sample) is not an original. Answers about another file, foreign hosts, absent originals and failed/blocked metadata (401/403/429/503, size/time limits) add no original-tier candidate; the existing guessed fallbacks stay lower-tier and every candidate still passes MIME verification. An answer is the same file only when the selected hash, `post.md5`, `media_asset.md5` and any hash named in the declared URL agree (an opaque declared URL is kept as written). When a preview, sample, size variant or `/jpeg/` conversion is selected on these boards, the pipeline skips the unbound generic md5 lookup, admits no other rendition or other-hash file, and without a verified original refuses the save (`NOT_FOUND`, no status invented) instead of saving the selection. Danbooru/rule34.xxx metadata was challenge-gated from an isolated profile (worker request 403); later user checks report working tested booru deployments without establishing every layout.

Native GIFs remain GIF. Only positively identified X/Reddit animations are converted from MP4. Ordinary videos and RedGIFs remain video. Above the 30-second animation threshold, save the original MP4; conversion errors do not create a renamed MP4 or a poster.

GIF processing: 50 MiB input, 30 seconds duration, 150 frames, 640 px maximum dimension, 15 MiB encoded output and 45 seconds total. Pixiv originals are acquired by the manager's staging like other files: exact declared URL with the DNR Referer rule, receiving progress, 60-second stall timeout (NETWORK_TIMEOUT), signature equal to the expected image type, declared length; a 50 MiB cap travels with the durable manager job (retry and restart included) and staging refuses a declared length above it before writing and a received body above it before writing that chunk (SIZE_EXCEEDED, partial file removed, nothing exported). A final probe that gets no answer defers to that byte check; an answered probe still decides. The resolver's declared original of the same illustration is original-tier, so a probe deadline cannot fall back to the preview. RedGIFs provider JSON: two requests within eight seconds, each capped at 256 KiB while reading; guest tokens stay in the frame. A RedGIFs save fixes its clip when the frame proves the selected player (an inline Save's one-shot token, or a context-menu gesture capture that is still the document's latest and unchanged); during the provider lookup that clip stays fixed (the player may reload, scroll away or be recycled) and only a replaced document, a navigation away or, for an inline Save, a page that is no longer the provider's own top player page refuses.

Admitted selections (UNIVERSAL-SELECTION-SNAPSHOT-01): before admission every existing sender, frame, document, gesture, freshness, one-shot, ownership and whole-list check applies. At admission the selection is frozen: exact source addresses (signed queries kept), post/clip/asset ids and a proven author. X and Reddit "Save all" freeze every slot's descriptor or refusal when the batch opens; Zerochan and Sankaku fix the post id (and file hash) when their page read starts (Zerochan re-admits the gesture owner right before that read, in the same document); a Pixiv feed batch is bound at the click to the proven preview's artwork id and its complete validated list. Afterwards scrolling, unloading or DOM recycling cannot add, drop or redirect a slot or change an author; provider answers must still name the admitted post/clip/hash, and a replaced document or a navigation away still stops work that has not started. An X batch player is recovered by its post id, not a stale page point.

Reddit HLS accepts only the supported finite, unencrypted same-asset Reddit H.264/AAC path, including selected fMP4/byte-range cases. Input is capped at 128 MiB and output at 160 MiB. This is not a generic HLS/DASH or DRM implementation.

Eligible owned `NETWORK_FAILED` exports can resume once through the browser's existing download ID. The manager retains prepared bytes after export failure for explicit local retry without a second source GET. It respects an observed Retry-After deadline and bounded explicit retry admission; it never silently refreshes a source or blindly duplicates an uncertain export.

Queue pause stops admission of new byte-transfer jobs; active jobs continue. Source/owner resolution starts immediately to preserve gesture and DOM evidence. Deferred post-resolution admission and proven source-range resume remain separate work; post-batch totals are implemented. Metadata is in private IndexedDB; pending jobs retain exact signed source URLs there, never in shared diagnostics. Storage quota and browser eviction can still interrupt acquisition.

Post-batch progress uses the same private queue record, with a finite service token (x/reddit/pixiv/pawchive) and up to 100 proven slots. A slot binds its operation before enqueue; a job determines saved only after browser/directory confirmation. Pre-job refusals, duplicates, cancellations and unstarted items settle separately. Count changes notify only after durable writes; rollback cannot announce tentative counts. Retry replaces its slot, startup reconciles unfinished preparation without silently rediscovering a post, and pruning follows remaining jobs/diagnostics. A partial Pawchive flag qualifies the known available-item total; NOT_ARCHIVED remains its own diagnostic operation, not an invented downloadable slot.

## Storage and UI

The MediaLatch rename preserves existing internal message/DOM identifiers and storage keys, including the `SavedImages` default folder. No migration or reinstallation is needed. `SOURCE_BASELINE.json` retains the original import identity.

The preview uses the original MediaLatch mark with theme colors in the full page, compact popup and toolbar: Violet retains purple, Blue uses blue, Dark uses graphite and Light uses a silver tile with a dark glyph. Toolbar PNG variants are derived from `icons/source.svg` and the UI brand tokens; the worker applies the saved `uiTheme` on cold start and changes, serializing icon writes separately from badge updates. Manifest identity assets stay the original Violet mark.

Interface layout (UI-REDESIGN-01): each theme in `ui/src/index.css` fills the same semantic roles (page, panel, control fill, hover, `selected`, border, control edge, focus/progress, primary, secondary and primary text), so the components carry no theme-specific code. Section text has a page title, a section title and its purpose, then body and caption sizes. The full page has a top bar (mark, theme, language) above a vertical section list on pages at least 768 px wide; narrower pages use a horizontal, scrolling tab row. Both are the same Radix tablist, with the matching arrow keys. Each section has a visible heading and a single level of panels. A download bar is determinate only while bytes are received with a known total; preparation, checking, the wait before saving and the export are indeterminate (striped and still under reduced motion), and queued or finished jobs have no bar. Page notices and inline media buttons use the same palette values.

First-run welcome: only `runtime.onInstalled` with reason `install` opens `popup/popup.html?welcome=1`; a failed tab open is logged and never blocks installation work. `ui/src/core/onboarding.js` treats that URL as the unfinished install welcome, so reloads keep it until an explicit Continue writes the single `firstRunGuideDismissed` marker; nothing is written on load, an existing true marker is never reset, existing preferences are not migrated, and old profiles never see it. There is no manual reopen or tutorial button. The welcome is an exclusive view of the full page: while the marker read is pending or the welcome is shown, the tabs, panels, Save bar and footer stay mounted but `hidden` (drafts and controllers survive). Saving is selected behind it, so hidden Downloads acknowledges nothing, and the first frame after a successful marker write reveals and focuses Saving; a failed write keeps the welcome with a retryable error. It starts no download and asks for no permission.

Settings use `chrome.storage.local`. A failed settings read keeps the form disabled, prevents saving defaults over unread preferences and offers Try again through the same `load()`; a loaded draft with unsaved changes is never reloaded over. `dirty` compares the eight explicit-Save fields with the last successfully loaded/saved values, plus a selected directory handle not yet written (even with an unchanged ID). Edits made during an awaited save stay unsaved. The Save bar shows loading, saving, an error (kept until the next attempt), then unsaved changes, and success only while the form matches storage; success messages clear themselves. Theme, language and notification preferences stay immediate. Relative paths are validated by the same folder helper in UI/runtime.

Download-manager errors are explained in both managers through `ui/src/core/present.js`: Chrome interruption reasons and manager codes map onto the existing `lib/feedback.js` categories (`classifyFailure`/`categoryText`); a few codes without a category there (storage quota, missing prepared file, expired source, batch limit, folder access/write, uncertain export) have their own catalogue texts. Unknown codes are shown as undetermined; the raw code stays on a small secondary line. Retry/export eligibility is unchanged. The same code texts are applied to the matching failed record row and details, so they never contradict the manager card; the recorded category, stage and code lines stay as evidence. A failed list refresh keeps the last cards and progress, shows the error with Try again, and is distinct from loading and from an empty list. `downloads.load()` called during an automatic read resolves only after the read it queued, so Try again stays busy (focusable, `aria-disabled`) until its own outcome and then hands focus to the recovered list.

Session diagnostics use `chrome.storage.session` with the existing bounded retention. Statistics use private IndexedDB global and finite per-site counters plus compact per-operation contributions without the old entry/time cap; the pre-statistics history (`imageSaverHistoryV1`) is only read, once, as their seed, and is never written, pruned or listed. Recording is configurable and clearable. A clear boundary excludes old operations from replay; only retained legacy data can be imported. See [Privacy](PRIVACY.md) for exact scope.

Statistics migrate earlier aggregates unchanged into unattributed totals, replacing old-format replay contributions atomically when proven site metadata becomes available. Detailed board buckets remain stored separately; the UI sums them into one Booru view and lists only populated services (plus an empty current selection until changed). All sites remains the default. Recording and clear are global; failures keep last-good totals. Private queued jobs retain a normalized owning-service token for retry attribution after feedback eviction; it never authorizes a fetch or enters public job snapshots.

Page notices use the originating tab's top frame and captured HTTP(S) origin, never the active unrelated tab or desktop notification API. The session record retains this route through worker restart; reports and statistics omit it. Closed, navigated or restricted tabs leave the outcome in Downloads and the failure badge. Success opt-out, terminal outcome timing and cancellation silence remain intact.

Ordinary single saves use a stable series card in the closed Shadow DOM. X/Reddit/Pixiv/Pawchive batches instead keep one card per worker batch, using committed slot counts shared with the managers; partial-import qualifiers and independent diagnostics remain distinct. Explicit dismissal suppresses that batch, updates preserve focus, and worker restart reconciles counts before delivery. The ordinary series behaves as follows. Single results retain their explanation; subsequent results update localized success/error counts, coalesced at most every 500ms, without remounting the card. All eligible successes reach the renderer instead of being dropped by a worker burst cap. If success notices are disabled during the series, the summary shows only errors. Ten seconds without a result starts a new series; a hovered or keyboard-focused card remains in place. Explicit dismissal suppresses continuing arrivals until that idle break. The v2.0.0.31 preview retires the card on successful manager opening without muting future results, so returning and saving again works even where tab visibility events are unavailable. Counts and deduplication remain part of the continuing series. Recent duplicate IDs are bounded to 256; worker notification idempotence remains authoritative. Expiry pauses while hidden, hovered or keyboard-focused. Manager actions use the latest notified operation and validate its originating tab/origin and stored terminal record again. Themes, keyboard focus and reduced motion remain supported. The published v2.0.0.30 still suppresses continuing arrivals on manager opening; v2.0.0.29 keeps its earlier individual-notice stack.

Blue, Dark and Light themes persist and synchronize between pages. The toolbar popup shows byte-transfer controls; the full Downloads page merges progress, controls and expandable result/report details into one card per job. Retained notification deep links can still open old diagnostics. Terminal removal lives inside expanded full-manager details; the repeated row tooltip and broad hover fill are absent. Removing a card first durably clears its terminal diagnostic, then removes the queue record/file; unreadable storage, active records or pending statistics delivery refuse deletion. Aggregate Statistics are not cleared by deleting download cards. Long localized tab names use a scrollable row with keyboard focus visibility.

The UI build targets Chromium 120 and emits local scripts/styles with no remote runtime code. `npm run build --prefix ui` regenerates `popup/`; the parity check rebuilds into a temporary folder and compares bytes. Notices are generated separately after dependencies or their licences change.

UI motion uses shared 120ms feedback/exit and 180ms entry/disclosure timings with consistent easing. CSS animates Radix menus/tooltips through their existing mount/unmount lifecycle; disclosure padding stays inside the measured wrapper to avoid a closing jump. Panels remain mounted, and byte progress and bulk removal are not delayed by animation. Page-notice dismissal releases focus/actions immediately while its visual card fades for 120ms; new arrivals retire fading cards before admission, limiting batch notices to four cards alongside the ordinary series card and protecting hovered/focused batch cards. Reduced motion removes effects, including notice exits, without changing the outcome or controls. Native browser popup windows and context menus retain browser-controlled behavior.

Committed language changes animate the existing page from 65% to full opacity for 180ms. Initial preference hydration and failed writes do not animate; a new change, page unmount or reduced-motion preference cancels the effect. Translations, document language and title update together without remounting controls or delaying persistence. Human-facing X platform labels use `x.com`; stored site identifiers, diagnostic fields and actual folder paths remain unchanged.

GitHub checks use the fixed `xhthc/MediaLatch` releases endpoint. The old repository cache is ignored. No release-supplied HTML or navigation URL is trusted, and no extension code is installed by this controller.

## Release and validation

The worker modules listed in the runtime layout are classic scripts that `background.js` imports in one ordered block before any of its own code runs; no module reads a `background.js` binding while it loads. Their declarations share the worker global scope, so a module's function may call another module's or the entry point's at run time. Selected-owner proofs, signed addresses, MIME validation and transport policy are unchanged by this organization.

`lib/worker/offscreen.js` creates a controller with explicit browser, messaging, download maps, tracking and manager-busy dependencies. Its ownership, creation/close single-flight and recovery state belong to that controller. A worker bridge preserves existing call order and interfaces. Unknown persisted ownership and unavailable download lookups still block destructive cleanup.

`lib/download_contracts.d.ts` describes the existing download snapshot, commands and UI state. The downloads controller is checked with `@ts-check`; its React view infers the store type. Worker sender checks and runtime validation remain mandatory: the declarations do not validate message contents. Compile-only negative cases check misspelled commands/states and numeric job IDs. The original MIME/resource integration cases now run from `tests/cases/media_lifecycle.cjs` in their original order with the same shared fixtures; `tests/test_worker_offscreen.js` also checks the controller directly.

Run `node tools/verify.mjs --ui` after building. It includes syntax, offline regressions, UI typecheck/render and source/build parity. Packaging reads only committed allow-listed runtime files and includes licence notices. Archive metadata records source commit, version, per-file hashes and ZIP hash.

Offline mocks and render tests do not prove native browser behavior, actual downloaded bytes or audio. Live acceptance is recorded separately. The large test files remain existing integration boundaries.

Pixiv feed previews with an explicit matching artwork link read the bounded pages API once and save only its declared same-artwork originals (up to 100). Opened-artwork media remains a single selection. The batch needs the click's proven admission; after metadata lookup only the admitting document (same documentId and URL) must remain, not the preview, before any batch item starts. Internal WeakSet provenance carries each declared plan; caller-supplied plan fields have no authority. Protected page acquisition is capped at two in-flight handlers per batch to bound buffered image preparation. An observed HTTP 429 stops further admission in that batch and records skipped pages as rate-limited; already admitted pages may finish.

All existing post-batch providers (Pixiv, Pawchive, X and Reddit) use the same 100-item ceiling. Content controls and worker validation agree. X/Reddit DOM enumeration is bounded at 400 media nodes and refuses truncated lists. Pawchive refuses an oversized post before probing any item instead of silently saving a prefix. The acquisition manager retains its three global/two per-origin slots; the larger count does not increase network concurrency or authorize whole-page collection.

X/Reddit batch ownership proofs retain their existing three-minute lifetime. A long-running batch can refuse later items after expiry or a changed owner/list; increasing the count does not extend stale proof validity. Batch totals do not extend proof validity; progressive proof renewal remains separate work.

Zerochan feed metadata is read in the pinned selected page session, with a bounded same-origin JSON request and unchanged source/anchor/document checks. The worker admits the selected owner before that lookup (a refused or unproven owner makes no request; only a frame that cannot be scripted at all keeps the id-bound extension route), runs the read pinned to the admitted document (a lost document, a rejected injection or a missing answer refuses, never the extension route) and validates the declared same-post HTTPS original before normal MIME probing; the preview may scroll away meanwhile. Opened-post selection retains the DOM original-link route; previews cannot become successful original saves when lookup fails.

## Source organization

Site content scripts live in `content/`; their manifest matching, injection order and frame scope are unchanged. Each runs in its own isolated world, so a helper shared with the worker or another content script is a separate copy unless a `lib/` file is listed in both (as `lib/debug_journal.js` and `lib/i18n.js` are). The offscreen document keeps its own copies of the URL-log sanitizer and protected-host check for the same reason. Offline checks live in `tests/`; binary media and captured Reddit structures are grouped under `tests/fixtures/generic-media/` and `tests/fixtures/reddit/`. Local media servers and AVIF generation tools live in `tools/fixtures/` and resolve fixture paths from their own location. The worker's modules live under `lib/worker/` and are listed in one block at the top of `background.js`; declarations are not duplicated in the entry point. Keep serialized `executeScript` functions self-contained. UI source and generated popup continue to use the existing React/Vite build.
