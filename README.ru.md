# Image Saver

[Manifest V3](manifest.json) · [Тесты](test_suite.js) · [English version](README.md)

Image Saver — расширение для Chromium, которое находит, проверяет и сохраняет доступные изображения, видео и анимации выбранного объекта. Оно предпочитает полноразмерные источники, если их удаётся определить и проверить.

## Возможности

- Один пункт сохранения для изображений, обычных GIF и доступных прямых MP4/WebM.
- Правила для отдельных ресурсов и общий поиск через ссылки, `srcset`, атрибуты оригинала и CSS-фоны.
- Настоящие зацикленные GIF из подтверждённых анимаций X `tweet_video` и Reddit GIF-as-MP4.
- Кнопки копирования ссылок на посты и видео в X, Instagram, TikTok и YouTube Shorts с независимым выбором домена для превью.
- Подпапка загрузок с сохранением в одну папку или по сайтам и типам медиа.
- Обратная связь о сохранении: уведомление и список в popup сообщают о завершённых сохранениях и видимых ошибках (сайт, фактический тип/расширение, статус конвертации, измеренный или оценочный размер) и дают копируемый отчёт об ошибке без секретов.
- Локальная обработка без телеметрии и собственного сервера расширения.

Наличие resolver-а и проверка в настоящем браузере — разные сведения. Описанные ниже пути показывают поддерживаемые механизмы, а не гарантию для каждой разметки.

## Установка

1. Скачайте доступный архив исходников или клонируйте репозиторий:

   ```bash
   git clone https://github.com/xhthc/image-saver-extension.git
   ```

2. Откройте `chrome://extensions` в браузере на базе Chromium.
3. Включите **«Режим разработчика»**.
4. Нажмите **«Загрузить распакованное»** и выберите папку с `manifest.json`.
5. После обновления перезагрузите расширение и обновите вкладки затронутых сайтов, чтобы их content scripts соответствовали загруженной версии.

Для загрузки и использования расширения не нужны ни сборка, ни Node, ни npm: страницы интерфейса в `popup/` — закоммиченные готовые файлы.

## Использование

Расширение регистрирует один прямой пункт сохранения в нативном меню для изображений, видео, анимаций и поддерживаемых CSS/overlay-целей, без подменю Image Saver. Проверка этого исправления меню в нативном Chromium пока ожидается.

Нажмите правой кнопкой мыши по нужной картинке, ссылке, видео или анимации и выберите действие Image Saver. Если сайт перехватывает меню, попробуйте **Shift + правую кнопку мыши**.

| Выбранное медиа | Результат |
|---|---|
| Статичное изображение | Лучший проверенный доступный источник изображения |
| Обычный анимированный GIF | Исходные GIF-байты |
| Обычное прямое MP4/WebM-видео | Проверенный файл в исходном формате с уже имеющимся звуком |
| Подтверждённая анимация X `tweet_video` | Настоящий зацикленный `.gif` |
| Подтверждённая анимация Reddit `preview.redd.it/*.gif?format=mp4` | Настоящий зацикленный `.gif` |
| Видео RedGIFs | Исходное видео без автоматической конвертации в GIF |

В зависимости от объекта пункт называется **Image Saver: Save image**, **Image Saver: Save video** или **Image Saver: Save GIF animation**. Обычные GIF могут сохраняться через действие для изображения. Ошибка конвертации не приводит к сохранению переименованного MP4 или постера.

### CSS-фоны и простые overlay

Статус: реализовано в черновом PR #11 (ветка `claude/gen-01-css-overlay`), в `main` не входит. Проверка пользователя в нативном Chromium ещё не получена, поэтому в реальном браузере это пока не подтверждено.

- Нажмите правой кнопкой по карточке, картинка которой задана CSS-свойством `background-image`, либо по прозрачному слою поверх одного изображения, видео или фона. На http(s)-страницах Chrome предложит общий пункт сохранения; его подпись соответствует выбранному медиа либо показывает «Save media under cursor», когда тип оригинала неизвестен. На x.com/twitter.com используется тот же общий пункт с прежним путём выбранного X-плеера. На пустых местах пункт скрывается по подсказке страницы; если подсказка опоздала, выбор пункта отказывает без загрузки.
- Ровно один http(s)-ресурс должен принадлежать выбранному элементу или лежать прямо под overlay, который его перекрывает, в том же контейнере и без второго ресурса. Обычные действия для изображения, ссылки и видео не меняются.
- Отказ (значок ERR, без файла и без запроса) при нескольких фонах в одном элементе, фоне предка (подпись внутри карточки), фоне `html`/`body`, overlay над двумя ресурсами, не-http(s) источниках и цели, которая изменилась, сместилась или была заменена между кликом и выбором пункта.
- Не охвачено: blob/MSE/HLS/DASH, кадры `about:blank`/`srcdoc` и реальное AVIF.

### Какая цель выбирается

Правило одно для любого http(s)-сайта, списка сайтов нет. Выбранная цель — изображение, GIF, видео, прямая ссылка на медиа, CSS-фон или однозначный overlay под правым кликом; она проверяется заново при выборе Save. Пустое место, текст, подпись, обычная навигационная ссылка и контейнер, в котором просто лежит изображение, целью не являются. У Chrome нет события до открытия меню, поэтому страница заранее сообщает (когда курсор остановился, при каждом правом нажатии и для клавиши меню), есть ли под ним цель, и единственный пункт сохранения отсутствует в меню там, где цели нет (он показывается или скрывается, серым не бывает; по возможности: самое первое меню после быстрого движения может ещё показать прежнее состояние), а клик, который всё же до него дошёл, отклоняется (ERR) без сохранения и без запросов. Подпись пункта зависит только от выбранной цели текущего клика: «Save image», «Save GIF» (файл GIF), «Save GIF animation» (подтверждённая анимация), «Save video» или нейтральная «Save media under cursor», когда тип оригинала неизвестен (фоновая карточка или превью booru, чей оригинал может быть GIF или видео, пока метаданные самой записи не скажут иначе); подпись прошлого клика не сохраняется. Удалённый, изменившийся или переиспользованный элемент не подменяется другим медиа (соседней карточкой, другим плеером, слайдом, кадром или прошлым кликом). Выбранный blob-плеер остаётся допустимой целью для имеющегося восстановления провайдером. Реализовано в черновом PR #11; подтверждение пользователя в нативном Chromium ещё не получено.

Проверка: из каталога этой ветки запустите `node tools/gen01-frame-acceptance-server.js 8765`, перезагрузите распакованное расширение из той же папки и обновите `http://localhost:8765/css.html`. Страница показывает ожидаемый файл для CSS1–CSS14 (включая CSS10b). Для CSS8, CSS9 и CSS14 после правого клика подождите минимум секунду, затем выберите Save.

Чтобы скопировать ссылку на пост, нажмите значок цепочки возле действий выбранной публикации в X, Instagram, TikTok или YouTube Shorts. Кнопка копирует каноническую ссылку с выбранным доменом. Она не публикует пост и не скачивает видео.

### Статусы на значке

| Статус | Значение |
|---|---|
| `...` | Поиск и проверка медиа |
| `DL` | Идёт скачивание |
| `OK` | Скачивание завершено |
| `RATE` | Ограничение запросов сервером |
| `AUTH` | Требуется авторизация или доступ запрещён |
| `ERR` | Медиа недоступно или операция завершилась ошибкой |

## Настройки

Popup на панели браузера компактный: пять последних результатов (имя файла, статус, сайт, тип, время) и кнопка-шестерёнка в правом верхнем углу шапки, которая открывает раздел **Сохранение** полной страницы расширения в новой вкладке (popup закрывается только после открытия вкладки). Список последних результатов виден только при включённой записи истории (по умолчанию выключена); пока она выключена, popup показывает небольшое предложение «Включить историю» (включает запись только после вашего клика и успешной записи настройки) и кнопку «Скрыть» (выбор запоминается отдельной настройкой, больше ничего не меняется), а после скрытия остаются только шапка и шестерёнка. Включить историю можно в любой момент на полной странице. Ошибки, уведомления и значок ошибки от этого не зависят. История и статистика доступны на полной странице или через «Открыть на странице истории» в раскрытом результате. На полной странице пять разделов: **Статистика и история** (переключатель и кнопка очистки истории, статистика по сохранённой истории, недавние результаты, отчёты об ошибках), **Сохранение** (корневая папка, одна папка или сайты/типы), **Уведомления** (уведомления об успехе; ошибки видны всегда) и **Embed** (независимые адреса ссылок для X, Instagram, TikTok и YouTube Shorts; они меняют только ссылки, которые копируют кнопки). Раздел **Обновления** проверяет GitHub Releases и поясняет ручную установку. Разделы открываются напрямую: `popup.html#history|saving|notifications|embed|updates`. Расширение сохраняет в настроенную подпапку загрузок без запроса «Сохранить как», включая Save all; прежняя настройка «Всегда спрашивать, куда сохранять» больше не действует. Кнопка **Сохранить настройки** (разделы «Сохранение» и «Embed») сохраняет эти два раздела; переключатели истории и уведомлений применяются сразу. Статистика описывает только сохранённую историю (не более 50 операций за 7 дней), а не итоги за всё время; известный суммарный размер складывает только измеренные размеры успешных сохранений и показывает, для скольких он известен.

| Настройка | Поведение |
|---|---|
| Подпапка для сохранения | Относительный путь внутри «Загрузок»; по умолчанию `SavedImages`. Пределы: 120 символов и 8 вложенных уровней (popup отклоняет более длинный ввод); уровни `.`/`..` отбрасываются, точки внутри имени сохраняются, зарезервированные имена Windows (`CON`, `NUL.txt`) получают суффикс `_`; пустое значение сохраняет прямо в «Загрузки» |
| Организация скачиваний | В одну папку (`single`, по умолчанию) либо по сайтам и типам медиа (`by_site_and_type`, например `<подпапка>/<сайт>/<pic|video|gif>/`). Сайт — это HTTP(S)-страница, которой принадлежит медиа, а не его CDN; для неизвестных сайтов используется имя хоста |
| История сохранений | Вести локальную историю завершённых сохранений (**по умолчанию выключено**; запись идёт только при явно включённой настройке, нечитаемая настройка считается выключенной). Выключение останавливает запись, но уже сохранённые записи остаются до нажатия «Очистить историю» |
| Уведомления об успехе | Уведомлять о завершённом сохранении (по умолчанию включено; сохраняется сразу в разделе «Уведомления»). Ошибки всегда показываются в списке popup и в уведомлениях |
| Домен ссылки на пост X | По умолчанию `x.com`; дополнительно `fixupx.com`, `cunnyx.com` |
| Домен ссылки на пост Instagram | По умолчанию `instagram.com`; дополнительно `oginstagram.com`, `kirkstagram.com` |
| Домен ссылки на видео TikTok | По умолчанию `tiktok.com`; дополнительно `tnktok.com`, `d.tnktok.com` |
| Домен ссылки на YouTube Shorts | По умолчанию `youtube.com`; дополнительно `yfxtube.com`, `koutube.com` |

Выбор домена для каждого ресурса независим. Альтернативные домены предоставляют сторонние превью для мессенджеров; `d.tnktok.com` — ссылка на прямой медиа-эмбед, а не команда скачивания MP4. Расширение формирует ссылки локально. Доступность превью зависит от сервиса, публикации и принимающего приложения.

## Обновления (ручная установка)

Откройте **Обновления** на полной странице расширения (`popup.html#updates`). При открытии вкладки проверяются опубликованные GitHub Releases не чаще раза в сутки; **Проверить сейчас** запускает проверку сразу. Пока вкладка закрыта, проверок нет. По умолчанию проверяются только обычные релизы; канал **Обычные и beta-релизы** включает и prerelease. Ошибки API показываются явно; указанная дата относится к последней успешной проверке.

Для автоматической проверки нужен **публичный репозиторий**. Релизы закрытого проекта недоступны анонимно: проверка сообщает об этом, не запрашивая токен. До публикации открывайте GitHub вручную через свой аккаунт в браузере.

Проверка сравнивает до четырёх числовых компонентов версии, пропускает черновики и неподдерживаемые теги версий и рассматривает первые 100 релизов. Тег релиза должен совпадать с `manifest.version`, допускается префикс `v` (например, `v2.0.0.21`); для beta используйте отметку prerelease на GitHub. Один тег или draft PR не является опубликованным релизом.

Для установки откройте релиз и скачайте готовый ZIP расширения из **Assets**. Дождитесь завершения сохранений, распакуйте архив, замените файлы в **той же папке расширения** и нажмите **«Перезагрузить»** на странице расширений браузера. Не удаляйте установленное расширение. Проверка не скачивает и не устанавливает обновления и не исполняет удалённый код.

Отправляется только анонимный запрос к публичному GitHub API релизов проекта: без cookies, токенов, URL медиа и истории сохранений. GitHub получает обычный сетевой запрос, включая ваш IP-адрес. Выбранный канал и небольшой кеш сведений о релизе хранятся локально. Новых разрешений нет.

## Ограничения

- Для прямого видео нужен доступный и проверенный источник. Сборка HLS/DASH, объединение отдельных дорожек звука и видео, DRM и обход защиты не входят в текущий контракт. Восстановление звука RedGIFs опирается на метаданные клипа без сборки отдельных аудиодорожек; проверка воспроизведения сохранённого звука в нативном Chromium пока ожидает подтверждения.
- Blob-плееры работают, когда resolver выбранного объекта может восстановить доступный источник. Произвольные объекты в памяти и содержимое canvas в общем случае не поддерживаются.
- GIF-кодирование ограничено длительностью, числом кадров, размерами, объёмом результата и временем выполнения. Текущие пределы указаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md); конвертация не является копированием MP4 без потерь.
- Папки создаёт сам Chromium только при сохранении файла. Полный относительный путь ограничен 240 символами (сокращается только имя файла). Папка типа определяется проверенным типом содержимого сохранённого файла; без такого признака — расширением имени, иначе `unknown-type`.
- Сохранение считается завершённым только после того, как Chrome сообщил о завершении загрузки. Размер измеряется по сохранённому файлу; до этого он помечается как оценка по заголовкам. Конвертер не сообщает размеры результата, поэтому размеры GIF показываются как неизвестные. HTTP-статус показывается только если конвейер его наблюдал (иначе «не наблюдался»). Ошибки остаются в списке popup (и отмечаются значком «!» до просмотра), даже если уведомления заблокированы или отключены для успешных сохранений. Открытые popup и полная страница следят за сохранениями: начавшееся, завершённое, неудачное или отменённое сохранение появляется или меняется на месте по событиям хранилища самого расширения (без опроса, одна подписка на список, снимается при закрытии страницы); сбой помечается «новое» и подтверждается только пока список виден, история обновляется, только если вы её включили. Автоматического повтора нет: повторите команду контекстного меню на том же медиа; устаревшие подписанные ссылки не используются повторно.
- Ошибка загрузки подтверждённого видео не приводит к незаметному скачиванию миниатюры. Авторизация, лимиты запросов, удалённое медиа и неподдерживаемый ответ могут помешать сохранению.
- Динамические ленты, галереи, встраивания и сторонние превью требуют проверки конкретного интерфейса и примера. Проверяйте скачивание и воспроизведение на реальной странице и в нужной сборке браузера.
- Адаптация Firefox и публикации в Telegram находятся в планах.

## Приватность и разрешения

Обработка медиа и настройки остаются в браузере. Расширение обращается к сайтам/CDN и существующим API ресурсов для поиска и загрузки выбранного медиа; телеметрии, собственного сервера и обязательного аккаунта расширения нет. На самом сайте может требоваться активный вход.

Manifest объявляет разрешения для загрузок, контекстного меню, хранилища, внедрения скриптов, DNR, offscreen и уведомлений, а также широкий доступ к HTTP/HTTPS для поиска медиа на разных сайтах. Точный список находится в [manifest.json](manifest.json).

Обратная связь о сохранении хранит не более 20 последних операций до 24 часов в session storage браузера (очищается при закрытии браузера). Запись содержит только имя сайта, хост и расширение источника, **базовое имя** сохранённого файла (без каталога и полного пути; после завершения берётся из загрузки Chrome, созданной расширением), сведения о типе и размере, состояние и код ошибки: без полных URL, путей, query-строк, cookies, Blob URL и самого медиа. Имена файлов не показываются в уведомлениях и не попадают в копируемые отчёты. Разрешение `notifications` нужно только для показа результатов сохранения. Отчёт об ошибке собирается из этих полей, показывается для проверки и копируется только по нажатию кнопки; никуда не отправляется.

История сохранений (полная страница расширения) хранится в `chrome.storage.local`: не более 50 завершённых операций за 7 дней (устаревшие записи удаляются из хранилища при запуске service worker и при каждом открытии или записи истории; пока браузер закрыт, очистка не выполняется); те же разрешённые поля и, если известна, каноническая ссылка на пост (пока только страницы статусов X; query и fragment отбрасываются, непроверяемый пост остаётся «неизвестным»). В ней нет ссылок на источник/медиа, Blob URL, подписанных параметров, путей и самого медиа; записываются только сохранения через это расширение. «Очистить историю» сохраняет границу очистки: операция, начатая до очистки, не добавится позже (даже при сверке незавершённой загрузки после перезапуска); если границу сохранить не удалось, очистка сообщает об ошибке.

К сторонним сервисам превью обращается браузер или принимающее приложение при открытии/отрисовке ссылки; при копировании расширение запросов к ним не отправляет. Планируемая отправка в Telegram будет отдельной добровольно подключаемой интеграцией; в этой сборке её нет.

## Разработка

Service worker, content-скрипты и offscreen-документ — обычный JavaScript без сборщика и npm-зависимостей во время работы. После правок перезагружайте распакованное расширение.

```bash
node test_suite.js
```

Две страницы интерфейса (`popup/quick.html`, `popup/popup.html`) — закоммиченный результат сборки только интерфейса в [`ui/`](ui/) (React, Tailwind CSS, компоненты [shadcn/ui](https://ui.shadcn.com) и два бесплатных компонента [Skiper UI](https://skiper-ui.com) с указанием авторства). Правьте `ui/src` и пересобирайте; обычному пользователю это не нужно:

```bash
npm ci --prefix ui
npm run build --prefix ui         # записывает popup/
npm run check:built --prefix ui   # падает, если popup/ не соответствует текущим исходникам
node test_ux_ui.js && node test_ui_render.js
```

Лицензии сторонних частей интерфейса — в `popup/THIRD_PARTY_NOTICES.txt`.

Тесты выполняются в offline Node harness. Для утверждений о браузере остаются нужны проверки в настоящем Chromium. Границы компонентов и реализованные ограничения описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
